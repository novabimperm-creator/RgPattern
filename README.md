# RgPattern

Небольшой архив медицинских снимков: рентген, КТ и МРТ. Базовая сущность — **случай**. У каждого случая есть система органов (обязательное поле), диагноз, описание, комментарии, фотографии и файлы других форматов.

## Возможности

- Список случаев и поиск по системе, диагнозу, описанию и комментариям
- Обязательное поле «Система» с предустановленными системами органов
- Просмотр изображений на сайте без входа
- Добавление случая кнопкой **+** (только авторизованные)
- Редактирование полей «Система», «Диагноз», «Описание», «Комментарии» (описание и комментарии — многострочные, без ограничения длины)
- Скачивание фото и файлов других форматов (DICOM, PDF и т.д.) — только после входа
- Добавление файлов внутри случая — авторизованные пользователи; удаление файлов и случаев — только суперадмин
- Регистрация новых пользователей — только суперадмин
- Адаптивная вёрстка для телефона и компьютера

Данные хранятся в каталоге `data/` (не попадает в git).

## Доступ

| Действие | Гость | Пользователь | Суперадмин |
| --- | --- | --- | --- |
| Смотреть случаи и снимки | да | да | да |
| Скачивать файлы | нет | да | да |
| Добавлять и изменять случаи | нет | да | да |
| Удалять случаи и файлы | нет | нет | да |
| Регистрировать пользователей | нет | нет | да |

При первом запуске откройте `/login` и создайте суперадмина (логин + пароль от 8 символов). Если раньше был общий пароль сайта, он переносится на пользователя `admin`.

После публикации в интернет **любой, у кого есть ссылка, видит случаи и снимки без входа**. Скачивание, правки и удаление по-прежнему закрыты логином.

## Запуск на своём компьютере

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

Для продакшена на той же машине:

```bash
npm run build
npm start
```

## Как опубликовать сайт в интернете

Это **не статическая страница**. Сайт сохраняет снимки и учётные записи на диске сервера, поэтому **GitHub Pages и Vercel не подойдут**: там нет постоянного хранилища, файлы пропадут после перезапуска.

Нужен хостинг с **постоянным диском** и обычным Node.js/Docker-сервером. Ниже — три рабочих варианта, от самого простого.

### Перед публикацией

1. Слейте этот код в ветку `main` (кнопка **Merge pull request** на GitHub).
2. Придумайте логин и **сильный пароль** суперадмина (от 8 символов).
3. Помните: после публикации гости видят снимки по ссылке. Не публикуйте адрес в открытых чатах, если архив не должен быть общедоступным для просмотра.

### Вариант 1. Railway (проще всего, около 5 минут)

1. Зарегистрируйтесь на [railway.app](https://railway.app) через GitHub.
2. **New Project** → **Deploy from GitHub repo** → выберите `RgPattern`.
3. После первого деплоя откройте сервис → **Settings → Volumes → New Volume**.
4. Точка монтирования: `/app/data`. Размер — по объёму снимков (для начала хватит 5–10 ГБ).
5. **Settings → Networking → Generate Domain** — появится адрес вида `https://….up.railway.app`.
6. Откройте `https://ваш-адрес/login` и создайте суперадмина.

Пересборка после `git push` в `main` происходит автоматически. Данные в томе `/app/data` при этом сохраняются.

### Вариант 2. Render

1. Зарегистрируйтесь на [render.com](https://render.com) через GitHub.
2. **New → Blueprint** и укажите репозиторий `RgPattern` (в репозитории уже есть `render.yaml`).
   Либо **New → Web Service** → Docker → тот же репозиторий.
3. Нужен тариф со **persistent disk**. Смонтируйте диск в `/app/data`.
4. Render выдаст адрес `https://….onrender.com`. Откройте `/login` и создайте суперадмина.

### Вариант 3. Свой сервер (VPS) через Docker

На сервере с Docker:

```bash
git clone https://github.com/novabimperm-creator/RgPattern.git
cd RgPattern
docker compose up -d --build
```

Сайт будет на порту `3000`. Повесьте перед ним HTTPS (Caddy, Nginx Proxy Manager или Cloudflare Tunnel) и откройте домен в браузере.

Если перед сайтом стоит Nginx, увеличьте лимит загрузки:

```nginx
client_max_body_size 200m;
```

### Что сделать сразу после публикации

1. Открыть `https://ваш-адрес/login` и создать суперадмина (логин + пароль).
2. Войти и зарегистрировать остальных пользователей (роль «пользователь» или «суперадмин»).
3. Создать тестовый случай, загрузить снимок.
4. Открыть сайт **без входа** (другое окно / режим инкогнито): список и картинки видны, кнопка скачивания недоступна.
5. Проверить вход с телефона.
6. По желанию привязать свой домен в настройках Railway/Render/DNS.

### Чего делать не нужно

- Не деплойте на **GitHub Pages** или **Vercel**: снимки и пользователи негде хранить.
- Не коммитьте папку `data/` в git.
- Не выкладывайте сайт без HTTPS: иначе cookie входа не будет работать надёжно.
- Не рассчитывайте, что «пароль закроет весь сайт»: просмотр архива открыт гостям.

## Форматы

Изображения (JPEG, PNG, WebP, GIF, BMP, SVG, AVIF и др.) показываются в галерее. Остальные файлы, включая DICOM, доступны для скачивания после входа.
