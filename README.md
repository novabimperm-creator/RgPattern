# RgPattern

Небольшой архив медицинских снимков: рентген, КТ и МРТ. Базовая сущность — **случай**. У каждого случая есть диагноз, описание, комментарии, фотографии и файлы других форматов.

## Возможности

- Список случаев и поиск по диагнозу, описанию и комментариям
- Добавление случая кнопкой **+**
- Редактирование полей «Диагноз», «Описание», «Комментарии» (описание и комментарии — многострочные, без ограничения длины)
- Просмотр изображений на сайте, скачивание фото и файлов других форматов (DICOM, PDF и т.д.)
- Добавление и удаление файлов внутри случая
- Пароль доступа и лимит на создание случаев (защита от ботов)
- Адаптивная вёрстка для телефона и компьютера

Данные хранятся в каталоге `data/` (не попадает в git). При первом запуске сайт попросит задать пароль — без него нельзя смотреть снимки и добавлять случаи.

## Запуск на своём компьютере

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

Для продакшена на той же машине:

```bash
npm run build
npm start
```

## Как опубликовать сайт в интернете

Это **не статическая страница**. Сайт сохраняет снимки и пароль на диске сервера, поэтому **GitHub Pages и Vercel не подойдут**: там нет постоянного хранилища, файлы пропадут после перезапуска.

Нужен хостинг с **постоянным диском** и обычным Node.js/Docker-сервером. Ниже — три рабочих варианта, от самого простого.

### Перед публикацией

1. Слейте этот код в ветку `main` (кнопка **Merge pull request** на GitHub).
2. Придумайте **сильный пароль** (от 8 символов). Его спросят при первом открытии сайта.
3. Помните: в архиве медицинские снимки. Не публикуйте ссылку в открытых чатах и не отключайте пароль.

### Вариант 1. Railway (проще всего, около 5 минут)

1. Зарегистрируйтесь на [railway.app](https://railway.app) через GitHub.
2. **New Project** → **Deploy from GitHub repo** → выберите `RgPattern`.
3. После первого деплоя откройте сервис → **Settings → Volumes → New Volume**.
4. Точка монтирования: `/app/data`. Размер — по объёму снимков (для начала хватит 5–10 ГБ).
5. **Settings → Networking → Generate Domain** — появится адрес вида `https://….up.railway.app`.
6. Откройте этот адрес в браузере, задайте пароль архива.

Пересборка после `git push` в `main` происходит автоматически. Данные в томе `/app/data` при этом сохраняются.

### Вариант 2. Render

1. Зарегистрируйтесь на [render.com](https://render.com) через GitHub.
2. **New → Blueprint** и укажите репозиторий `RgPattern` (в репозитории уже есть `render.yaml`).
   Либо **New → Web Service** → Docker → тот же репозиторий.
3. Нужен тариф со **persistent disk**. Смонтируйте диск в `/app/data`.
4. Render выдаст адрес `https://….onrender.com`. Откройте его и задайте пароль.

### Вариант 3. Свой сервер (VPS) через Docker

На сервере с Docker:

```bash
git clone https://github.com/novabimperm-creator/RgPattern.git
cd RgPattern
docker compose up -d --build
```

Сайт будет на порту `3000`. Повесьте перед ним HTTPS (Caddy, Nginx Proxy Manager или Cloudflare Tunnel) и откройте домен в браузере.

Если перед сайтом стоит Nginx, увеличьте лимит загрузки:

```nginx
client_max_body_size 200m;
```

### Что сделать сразу после публикации

1. Открыть выданный HTTPS-адрес.
2. Задать пароль архива (один раз).
3. Создать тестовый случай, загрузить снимок, обновить страницу — файл должен остаться.
4. Проверить вход с телефона.
5. По желанию привязать свой домен в настройках Railway/Render/DNS.

### Чего делать не нужно

- Не деплойте на **GitHub Pages** или **Vercel**: снимки и пароль негде хранить.
- Не коммитьте папку `data/` в git.
- Не выкладывайте сайт без HTTPS: иначе cookie авторизации не будет работать надёжно.

## Форматы

Изображения (JPEG, PNG, WebP, GIF, BMP, SVG, AVIF и др.) показываются в галерее. Остальные файлы, включая DICOM, доступны для скачивания.
